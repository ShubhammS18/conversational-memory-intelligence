## M2 post-APPROVE human quiz · in progress
- Q1 · design decision: Why must SQLite apply the complete current-state eligibility policy before FAISS search, while hydration repeats the policy afterward using the same trusted timestamp?
- Human answer: SQLite filters first so FAISS searches only memories currently safe and allowed for the user, excluding stale, incomplete, deleted, and unrelated records from candidates. Hydration repeats the checks because state may change after the initial lookup, and the same trusted time keeps both decisions consistent.
- Assessment: pass · correctly identifies deterministic pre-search policy precedence, defensive revalidation against state changes, and temporal consistency from one trusted timestamp
- Next quiz step: Q2 · edge case
- Q2 · edge case: A memory is active, indexed, owned by the caller, and not deleted or superseded. What should current-state retrieval do when the trusted time is exactly equal to its `valid_until`, and why?
- Human answer: exclude it from current-state retrieval because the approved end boundary is exclusive; at exactly `valid_until` it must not be ranked or added to context even though all other eligibility fields pass.
- Assessment: pass · correctly applies `now < valid_until`, the exact-boundary exclusion, and deterministic precedence before ranking and context construction
- Next quiz step: Q3 · change impact
- Q3 · change impact: Why is `deleted_at` only a read-side tombstone in M2, and what later behavior would accidentally expand this change into M7 forgetting work?
- Human answer: M2 only reads `deleted_at` to exclude a memory from search and context; it provides no operation that sets the marker or removes a FAISS vector. Adding a forget request that writes `deleted_at`, removes the vector, handles partial-failure retries, and authorizes the requesting owner would be M7 work.
- Assessment: pass · correctly separates M2 read eligibility from M7 owner-authorized mutation, derived-index removal, and failure/retry behavior
- Quiz result: pass · all three required categories—design decision, edge case, and change impact—were answered by the human and assessed as correct
