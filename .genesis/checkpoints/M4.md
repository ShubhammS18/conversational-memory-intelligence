## Approved pre-BUILD decision · 2026-09-06

- target: one nullable explicit `supersedes_memory_id`; no inferred target or
  multiple-target behavior
- target rules: same trusted owner; active and indexed; not already superseded;
  exact normalized subject and memory-type match; no self-reference or cycle
- authority: only `EvidenceAuthority.EXPLICIT_USER` (`explicit_user`) may create
  the link; ambiguous or `EvidenceAuthority.INFERRED` (`inferred`) input creates
  no supersession relationship
- ordering: validate first; persist the replacement as pending; publish its vector;
  then use one atomic SQLite transaction to mark the replacement indexed and write
  both relationship directions
- visibility: an indexed-vector-but-unacknowledged replacement remains
  `indexing_state=pending`, is non-retrievable, and cannot compete with the old
  target in current-state retrieval
- failure: replacement persistence failure, failed or uncertain FAISS publication,
  or atomic acknowledgement failure leaves the old target as the only current
  memory and creates no relationship; failed or uncertain publication remains
  governed by the existing M1 pending/indexed/failed and stable-ID
  duplicate-prevention contract, with reconciliation reserved for M8
- retry: only when durable publication of the exact stable vector ID is known may
  an identical retry skip embedding/vector publication and complete only the
  missing atomic SQLite transaction; otherwise it follows the existing M1
  publication retry contract and performs no relationship mutation until durable
  publication is verified
- reversion: create a new record; never reactivate an older superseded record
- binding: `M4-supersession-and-conflict-bindings`
- freeze boundary: locked M4 PLAN paths plus the unchanged five exact governance
  paths in `M4-freeze-boundary-exceptions`
